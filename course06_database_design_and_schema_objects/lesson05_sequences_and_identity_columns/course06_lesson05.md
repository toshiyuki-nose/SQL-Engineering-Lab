# Course 06 — Lesson 05: Sequences and Identity Columns

> **Generate identifiers reliably. Understand what Oracle guarantees—and what it does not.**

## 1. Overview

A relational database often needs unique identifiers for new rows. Oracle provides **sequences**, standalone schema objects that generate numbers, and **identity columns**, table columns whose values are generated using an internal sequence.

This lesson uses isolated `C06L05_` practice objects. It does not modify the established Book Store Database.

## 4. Sequences

A sequence is an independent database object. Its values can be used by more than one table, though this exercise uses one sequence for one table.

```sql
CREATE SEQUENCE c06l05_book_seq
    START WITH 1001
    INCREMENT BY 1
    NOCYCLE
    CACHE 20;
```

- `START WITH`: initial generated value.
- `INCREMENT BY`: amount added between generated values.
- `CACHE`: Oracle can preallocate sequence values for efficiency.
- `NOCYCLE`: do not wrap around when a configured bound is reached.

### 4.1 NEXTVAL and CURRVAL

- `sequence_name.NEXTVAL` advances the sequence and returns a value.
- `sequence_name.CURRVAL` returns the most recent value obtained by `NEXTVAL` **in the current session**. Before the first `NEXTVAL` in that session, `CURRVAL` is not defined.

Sequence values are **not transactional**: a rollback does not return consumed numbers. Cached values can also be lost, so a sequence is not a gap-free numbering system.

## 5. Sequence-backed Inserts

```sql
INSERT INTO c06l05_sequence_books (book_id, title)
VALUES (c06l05_book_seq.NEXTVAL, 'Database Fundamentals');
```

The primary key constraint enforces uniqueness; the sequence supplies candidate values. These are distinct responsibilities.

## 6. Identity Columns

An identity column is defined as part of a table and uses an Oracle-managed sequence internally.

```sql
CREATE TABLE c06l05_identity_always (
    book_id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title VARCHAR2(100) NOT NULL
);
```

### 6.1 Generation modes

| Mode | Generated when ID omitted? | Explicit non-NULL ID allowed? | Explicit NULL generated? |
|---|---|---|---|
| `GENERATED ALWAYS` | Yes | No | No |
| `GENERATED BY DEFAULT` | Yes | Yes | No |
| `GENERATED BY DEFAULT ON NULL` | Yes | Yes | Yes |

For `GENERATED ALWAYS`, an explicit value is rejected (commonly `ORA-32795`). For `BY DEFAULT`, an explicit `NULL` is not auto-generated and typically fails a NOT NULL constraint (`ORA-01400`). The `ON NULL` variant generates a value instead.

## 7. Sequence vs. Identity

| Consideration | Sequence | Identity column |
|---|---|---|
| Scope | Standalone schema object | Defined on a table column |
| Insert syntax | Explicit `NEXTVAL` (or a default expression) | Often omit the ID column |
| Reuse | Can be referenced by multiple tables | Associated with one identity column |
| Number gaps | Possible | Possible |
| Typical use | Shared or explicitly controlled generation | Straightforward table-specific surrogate keys |

Neither approach replaces primary-key constraints or guarantees contiguous numbering.

## 11. Engineering Notes

- Surrogate keys identify rows; they do not automatically encode business meaning.
- Never assume sequence values represent committed-row counts or reliable chronological ordering.
- Explicit IDs in `BY DEFAULT` tables can conflict with subsequently generated values; a primary key catches duplicates.
